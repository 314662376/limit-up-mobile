# limit-up-mobile

打板情绪看板的**手机版**：一列、最宽 520px，页面上只有 **3 个数字 + 2 条折线**，没有任何说明文字。

- 线上：https://314662376.github.io/limit-up-mobile/
- 电脑版（完整说明、公式推导、5 日图图例）：https://314662376.github.io/limit-up-sentiment/

## 与电脑版的关系

**同一份数据，两个前端。** 手机版不采集数据，历史归档直接跨域读电脑版仓库的
`data/`（GitHub Pages 对所有静态资源都发 `Access-Control-Allow-Origin: *`）：

```
DATA_BASE = 'https://314662376.github.io/limit-up-sentiment/data/'
```

所以采集任务只需要在电脑版仓库里跑那一套，这里不用配 Action，也不会多打同花顺接口。

`app.js` 是从电脑版复制过来的，只改了这些地方：

| 改动 | 说明 |
| --- | --- |
| `DATA_BASE` | 归档改读电脑版仓库的绝对地址 |
| `isNarrow()` → 恒 `true` | 本页永远是单列窄栏，图表参数固定用窄屏那套 |
| `curve tooltip` | 只留「时刻 + 数值」，去掉了 883900 / 上证 / 883918 明细 |
| 3 个数字的文案 | 第三个数字（封板率）只显示百分比，口径明细挪进 `title` |
| 5 日图图例 | 只留「颜色 → 哪一天」，不再挂百分比（那个数是基准，极易被误读） |
| 状态栏 / 提示文案 | 一律压到 2–4 个字（盘前 / 盘后 / 存档 / 基准未取到…） |

## 3 个数字与 2 条线

| 位置 | 含义 |
| --- | --- |
| 左 | ① 涨停情绪指数（中性基准 1.0000） |
| 中 | ② 打板收益（元 / 万元本金，中性基准 0） |
| 右 | **今日**非一字板封板率（实时累加；收盘后定格） |
| 上折线 | ① 的走势，y 轴固定 0.925–1.075 |
| 下折线 | ② 的走势，y 轴固定 −200–300 |

红 = 涨 / 强，绿 = 跌 / 弱（A 股口径）。第三个数字「封板率」高 = 情绪强 = 红。

第三个数字的取值顺序（**关键：任何一步都只认「今天」的数据**）：

1. 直连同花顺涨停池 / 炸板池，且返回的 `date` 就是今天 → 今日实时值；
2. 取不到时，读当天归档 `data/<今天>.json` 的 `self`（今天自己的家数，收盘后由采集任务写入）→ 显示收盘定格值；
3. 都没有 → 显示 `--`。

**绝不退到「上一个交易日」的数** —— 归档里的 `rate` 装的就是前一个交易日的家数，
早期版本错把它挂在这个位置，页面上看起来一切正常，只是数字是昨天的。
回归测试：`node scripts/verify-today-rate.js`（3 个场景）。

> 注：①② 两个公式的权重用的是**昨日**非一字板封板率（= 当天归档里的 `rate`），
> 与这个「今日」数字不是同一个东西 —— 手机上不单独占位，明细在折线的 tooltip 里。
